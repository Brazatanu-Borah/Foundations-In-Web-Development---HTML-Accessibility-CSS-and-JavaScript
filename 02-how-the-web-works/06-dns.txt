====
  Domain Name System 
  >> [Phone Book of the web / Context List of the Web]
  [IP Address] ... mapped to (by DNS) ... [Domain Name]

  82.16.4.25 <<------------DNS------------->> test.com


  MY COMPUTER COMMUNICATES WITH DIFFERENT SERVERS ON THE INTERNET


  >> just has the list of domain names and their corresponding IP addresses
  >> these pairs are called 'records'

  IP address -> the exact location of the website files


DNS Server is for
  Websites      : A Record
  Email address : MX Record
  >> other records called C name records

  👆 Hence, all public facing websites/devices/services must have a static IP address. if it keeps changing, we have keep updating our DNS record constantly


  If IP address changes, we must change the record in the DNS
    Most web service provides handles this efficiently with something called DDNS (Dynamic DNS)

    82.164.25 <<------------DDNS------------>> test.com

    Even when the ip address changes, the records get updated
      - the domain name remains the same, the server (website files) location remains the same
      - the connection gets updated


    When the server behind the ip address is our own PC
      - using the server mentioned in the earlier lesson
    When domain names changes , although IP address stays fixed


PING
=====
  google.com - first this thing goes to DNS
  DNS found the ip address associated with this ip address and gave it back to our terminal
  terminal again sent request to the specific ip address
  the server behind the ip address received the 'knock'
  the server then sent back the ping with a response to the terminal that sent the request (it remembers the route)

  nslookup
